## 基线与实际收益

- `src/capacity_changes.rs::borrow/borrow_and_update` 返回 `tokio::sync::watch::Ref<'_, u64>`，未说明 guard 持有读锁。Tokio 1.54.0 的 watch 源码明确指出长期借用会阻塞发送端、跨 await 可能死锁。
- `src/rayon_executor_service_state.rs::notify_async_changes` 同步调用 `send_modify`。持 guard 后在同线程调用 shutdown 会等待自己释放的锁；worker 发布受阻还会延迟 `run_one` 的后继派发。这是静态可解释风险，不是已动态复现的下游事故。
- `src/rayon_executor_service.rs::submit_callable_with` 在 admit 前创建 endpoint 和 job，拒绝只返回原因，消费原 callable。该契约已有说明，不能作为旧行为缺陷。
- `../rs-execution-services/src/execution_services/waiting_submission.rs::submit_cpu_callable_wait` 使用 `internal/owned_wait_task.rs` 中的 `Arc<Mutex<Option<T>>>` 保存一次性任务。新接口可让此类调用方直接保留被拒绝任务，减少包装逻辑；未测量性能收益。
- `../rs-tokio-executor/src/rejected_task.rs` 和 `try_submit_callable` 提供同类命名参考；RejectedTask 属于 Tokio crate，不能为了复用而让本库依赖 Tokio executor。

## 方案选择

采用兼容性增量：保留借用接口，补文档并增加复制读取；保留 ExecutorService，新增 inherent callable 提交 API。只补文档无法满足一次性任务重试需求；改公共 trait、跨仓抽取拒绝类型或全面重写调度会扩大范围，因此不采用。无需破坏兼容性，不新增依赖，不以版本发布为验收前提。

## RX-001：容量通知边界

新增以下非异步方法，保持 async-wait feature 门控：

```rust
pub fn generation(&self) -> u64 { *self.receiver.borrow() }
pub fn generation_and_update(&mut self) -> u64 { *self.receiver.borrow_and_update() }
```

两方法只返回复制值，guard 在方法返回前释放。generation 是可回绕的通知代数，不是剩余容量或严格计数；读取不保证后续接纳成功。第一方法不改变已读状态，第二方法标记当前代数已读。

保留 borrow 和 borrow_and_update 的签名。其英文 rustdoc 和双语用户指南都应明确：guard 持有读锁，应短时使用；不要跨 await、终止等待或调用 shutdown/stop/cancel 等可能发布通知的操作；需要记录值时复制后立即释放 guard。新示例优先使用 generation 方法。无需废弃接口或修改现有下游。

验证复制方法的已读语义，并用子进程和父进程截止时间验证旧借用确实阻塞发布、释放后恢复；不把预期死锁留在主测试进程。测试通过线程 channel 观察发布开始/完成，释放 guard 后必须完成；只有观察到阻塞前提后才判断预期行为。超时回收子进程。

## RX-002：归还任务的提交

新增本库自己的 `RejectedTask<T>`，放在 `src/rejected_task.rs`，从根模块导出。字段私有；提供 reason、into_parts，crate 内 new；Debug 只输出原因且不要求 T: Debug，不输出任务捕获数据；Display 委托原因，Error 不增加 T 的约束。行为参照 Tokio 同名类型，但二者是不同类型，不作跨仓抽取。

新增唯一提交入口：

```rust
pub fn try_submit_callable<C, R, E>(
    &self, task: C,
) -> Result<TaskHandle<R, E>, RejectedTask<C>>
where C: Callable<R, E> + Send + 'static,
      R: Send + 'static, E: Send + 'static;
```

Shutdown 优先于 Saturated。拒绝归还原始 C，不调用、不析构 C；调用方丢弃 RejectedTask 时正常析构。接纳是单次原子决策，不得在锁外先检查容量再提交。接纳成功后的完成、panic、关闭和容量统计保持原语义。

### 最小内部变更

把 state.admit 的输入保留为具体 job 类型直到接纳成功：

```rust
pub(crate) fn admit<J: QueuedJob + 'static>(
    &self, job: Box<J>,
) -> Result<Admission, (SubmissionError, Box<J>)>;
```

锁内维持原有生命周期检查、容量检查、ID 分配、accept、入队和 scheduled 更新顺序；错误返回原 Box，成功入队时才擦除类型。错误返回前释放 state mutex，原任务及 slot 的清理均由锁外调用方处理。不得调用用户工厂、下转型或引入预约提交状态机。

为 CallableJob 增加 crate 内 into_task(self: Box<Self>) -> C，拆出 task 并释放未接纳 slot；它只用于拒绝路径。该 slot 从未 accept、对应 handle 不向用户返回。回收后构造 RejectedTask。普通 submit_callable 委托 try_submit_callable，再将拒绝映射为原 SubmissionError；丢弃原任务仍在锁外。tracked 和 runnable 路径只适配新的内部 admit 错误形式，保持旧消费契约；删除接纳前 Box<dyn QueuedJob> 注解，保留具体类型。submit_callable_with 若不再有调用方可删除，不为保留 helper 引入额外泛型框架。

本轮不新增 try_submit、try_submit_tracked_callable，不修改共享 ExecutorService trait。调用任意旧提交接口拒绝时仍消费任务；文档必须区分旧接口与新 inherent API。

### 调用方与迁移

现有调用方无需迁移。需要重试者先订阅 capacity_changes，再将同一 C 传入 try_submit_callable；Saturated 时 into_parts 取回 C、等待 changed 后重试，Shutdown 时结束并由调用方处置 C。使用具名 helper 返回 impl Callable 或 impl FnMut 保持闭包类型一致，支持捕获一次性输入。

rs-execution-services 将来可用此循环替代 CPU 分支的 OwnedWaitTask；其 blocking 分支仍使用该 helper，不能整体删除。当前交付不修改下游仓库；在实施中可以通过 Cargo 临时配置 patch 指向本树进行下游验证，不能把 registry 版本的通过当成本树验证。README 只需新增一句能力说明并链接指南；两种用户指南提供等价、完整可运行的重试示例。
